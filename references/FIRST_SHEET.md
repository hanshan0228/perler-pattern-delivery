# 首稿质量规范 / First-sheet quality contract (v2.3)

## 目标与输入分流

- 默认交付：卡通人物 **带色号单页拼豆图纸**，不是画一张看起来像网格的图。若用户明确指定像素图或普通照片模式，按指定走；只请求底图/模拟效果时才单独交付底图/模拟图。
- 新肖像默认 87×87、最多 33 个 MARD 颜色（不是必须恰好 33 个）。58×58 可作为小尺寸备选，不擅自缩小用户指定尺寸。
- 已确认 MASTER 永远优先；新造型才重新生成。任何卡通源或客户原始照片只留在客户项目目录，不上传到公共 GitHub。

## 图像生成提示词（作为实际图像编辑任务，不是文本替代品）

> Edit the supplied photo into a clean, bust-length, precise hand-drawn flat-color cartoon portrait for a fuse-bead chart. Preserve pose, gaze, recognizable facial proportions, eye shape, expression, hairstyle silhouette, clothing and distinctive accessories. Make the face and important features large enough to remain readable at 87 by 87 pixels. Use broad contiguous flat color regions, 2–3 shades per main skin/hair/clothing region, controlled thin dark outlines only where useful, clearly separated eyes and mouth, simplified but recognizable accessories. Use a square composition, centered subject, keep the entire important silhouette and accessories inside the frame, plain warm ivory background. Avoid photographic texture, complex background, hair-by-hair rendering, excessive shading, gradients, tiny decorative specks and thick black contours. No grid, no bead texture, no color codes, no text, no legend. The exact MARD grid and legend will be generated by separate code.

Adjust important features to actual photo (not all subjects have flowers). Do not simply run smoothing/edge filters and call the result AI. Do not generate the final numbered chart with an image-generation model. An agent that lacks image-editing capability must request an actual cartoon source rather than switch to a visually inferior hidden fallback.

## Visual review (required before first user-visible chart)

Inspect the original, cartoon base and both candidate previews at thumbnail and full-size. Compare against approved style benchmark generated from `examples/approved_87x87.csv` (33 colors, 7569 beads, digest `8c7bcbb1ad12ac1257b38c89496b1924f93fb40cc06a50c7859d1d2b201e6fc5`). It is a **style** reference — never replace the new customer's subject with it. The user-approved 58×58 benchmark also remains unchanged.

The five fields in the review JSON mean:

- `recognizable_subject`: actual original pose, major facial features and expression are retained; not a generic substitute.
- `cartoon_not_photo_filter`: intentional illustration with coherent flat-color areas; not a smoothed photo.
- `framing_and_silhouette`: important silhouette, accessories and hair remain in frame; composition fills the board appropriately.
- `key_features_readable`: eyes, mouth, eyebrows, face contour, clothing/accessories read at actual bead resolution. No disconnected essential features.
- `clean_regions_and_no_artifacts`: no unintended speckles, dark grid seams, distracting text-like objects, accidental gradients or disproportionately noisy regions. Do not sacrifice essential one-cell details just to reduce noise.

Use concrete notes stating what was inspected and why the selected variant wins. If either cartoon stage or both variants fail, regenerate base (or revise palette/resolution only if allowed) in new folder and rerun. At most two corrective rounds per task. No falsely marked pass or pretend visual review. Preserve every approved matrix. If review cannot be performed, state that and stop; a hash is not aesthetic validation.

## Deterministic rendering and acceptance

`prepare` pads rather than silently cropping an important silhouette, produces two separate quantized candidates (central median vs area average) and review sheet. No automatic cleanup can delete a critical eye pixel. `select` requires review bound to the selected matrix digest and actual comparison image; its `candidate_sheet.png` is explicitly unapproved. `verify` checks required files, pinned palette, matrix and semantic pixels, exact color counts, legend and file hashes. It cannot certify aesthetic quality or that a human actually looked at the images. User confirmation triggers existing `freeze` and `deliver`; never auto-approve the candidate.

## Final user response

Lead with the selected candidate sheet; include a link to the high-resolution sheet and optionally matrix and zoomable chart. Briefly state grid, number of colors, beads, boards, validation and unapproved status. Do not present competing weak drafts to the customer unless requested. Do not present the original reference comparison as the main deliverable.
